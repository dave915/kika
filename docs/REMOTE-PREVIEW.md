# 접속 키로 보호하는 임시 원격 미리보기

## 현재 상태

원격 보호 프록시와 실행 도구를 구현했고 로컬 보호 테스트 9개를 통과했습니다. 사용자가 Cloudflare 중계 범위를 안내받은 뒤 **“열어줘”라고 명시적으로 승인하여 2026-09-09에 연결을 실행했습니다.** 주소 발급뿐 아니라 Cloudflare 연결 등록과 실제 공개 DNS 조회를 확인합니다. 현재 개인 접속 링크와 만료 시각은 `.data/remote-preview.json`에 보관하며 문서에 접속 키를 복사하지 않습니다.

## 연결 구성

- 관리 화면용 HTTPS 주소 → Cloudflare → `127.0.0.1:4180` 접속 보호 → 기존 관리 API·빌드된 UI `4174`.
- 배포 앱용 별도 HTTPS 주소 → Cloudflare → `127.0.0.1:4181` 접속 보호 → 기존 런타임 `4175`.
- Ollama는 Mac의 로컬 `11434`에서 계속 실행합니다. Ollama 포트를 터널로 열지 않습니다.
- 브라우저의 앱·API 요청과 응답은 Cloudflare를 경유합니다. AI 요청·응답도 이 경로를 사용하므로 Cloudflare를 신뢰하는 전제가 필요합니다. 접속 키는 다른 방문자의 접근을 막으며 중계 서비스에 대한 종단 간 암호화를 제공하는 것은 아닙니다.
- 관리·실행 서버나 개발 서버를 `0.0.0.0`으로 변경하지 않습니다.

## 보호 동작

1. 관리·런타임에 서로 다른 256비트 접속 키를 생성합니다.
2. 접속 링크의 fragment(`#access=...`)를 신뢰된 진입 페이지에서 소비한 뒤, 주소에서 제거하고 앱을 엽니다. 이미 로그인한 브라우저에서도 같은 진입 페이지를 거칩니다. 비신뢰 배포 앱의 실행 주소에는 키를 붙이지 않습니다.
3. 원격 세션은 별도의 `__Host-` Secure·HttpOnly·SameSite=Lax 쿠키를 사용합니다. 관리 세션과 런타임 세션은 서로 다른 호스트에 머뭅니다.
4. 키 없는 화면·API·파일 요청, 잘못된 Host·Origin 요청을 차단합니다.
5. 인증된 요청만 내부로 전달합니다. 외부 Cookie 전체나 임의 Authorization·사용자 신원 헤더를 전달하지 않습니다. 앱의 기존 CSRF·역할 검사는 유지합니다.
6. 모든 응답은 private/no-store입니다. 원격 링크와 키는 `.data/remote-preview.json`에 0600 권한으로 저장되며 Git에 포함되지 않습니다.
7. 8시간은 게이트의 최대 자동 종료 시간이며 가용성 보장이 아닙니다. Cloudflare 임시 터널은 그 전에 끊길 수 있습니다. Ctrl+C로 즉시 끌 수 있으며 기존 로컬 앱·Ollama는 유지됩니다.

이 키는 개발용 관리 화면 전체의 접근 권한입니다. 링크를 받은 사람은 현재 로컬 체험 역할 전환 기능에도 접근할 수 있으므로 본인의 미리보기용으로만 사용합니다. 이 방식은 Keycloak 등 회사 인증을 대체하는 운영 배포가 아닙니다.

## 승인 후 실행

현재 대화에서는 Cloudflare를 경유하는 원격 미리보기에 대한 사용자 승인을 받았습니다. 이 승인 범위 안에서 연결과 검증을 진행합니다.

```sh
npm run build
npm run dev
```

다른 터미널에서:

```sh
CLOUDFLARED_BIN=/path/to/cloudflared npm run remote:preview
```

기존 로컬 앱이 `npm start`로 실행 중이면 `MANAGE_ORIGIN=http://localhost:4174`도 지정합니다. 기본값은 `npm run dev`의 `http://localhost:5173`입니다.

연결이 완료되면 `.data/remote-preview.json`의 `accessUrl`이 사용자에게 전달할 개인용 링크입니다. 파일 안의 키를 로그나 저장소에 올리지 않습니다. 종료하면 파일을 삭제하고, 다시 실행하면 새 주소와 새 키를 생성합니다.

이 세션에서는 공식 `cloudflared` 2026.8.3 Darwin arm64 배포본을 임시 폴더 `/private/tmp/kika-tools/cloudflared`에 준비했습니다. GitHub 릴리스가 제공한 SHA-256과 일치함을 확인했습니다. 시스템 전역에 설치하지 않았습니다.

## 검증

```sh
node --test tests/remote-gate.test.mjs
```

9개 테스트: 익명 API·파일 차단, nonce CSP, 키·Host·Origin 검증, 쿠키 속성, 내부 헤더 전달, 런타임 링크의 안전한 진입 경로, 로그인 후 재진입 처리, 오픈 리다이렉트·키 교차 사용 방어, 로그아웃·만료.

실제 Cloudflare 터널은 연결 등록까지 완료되었습니다. 관리·실행 두 주소의 공개 DNS와 키 없는 API 요청의 401 차단을 확인했습니다. 원격 주소 발급만으로는 성공으로 처리하지 않으며, 외부 HTTPS 브라우저 로그인·저장·AI 응답을 별도로 검증합니다.

Cloudflare Quick Tunnel은 [공식 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)에 따라 임시 개발·시험용으로 사용합니다. 고정 주소나 가용성을 보장하지 않습니다.

## 실제 외부 접속 확인 결과

2026-09-09 실제 Cloudflare HTTPS 주소에서 Chrome으로 접속 키 자동 로그인과 URL의 키 제거, 프로젝트 목록과 인증된 저장, 실제 Ollama 응답, 별도 런타임 진입과 Secure·HttpOnly 쿠키 분리, 390px 화면 가로 넘침 없음 및 JavaScript 오류 없음을 확인했습니다.

## 1033 오류 복구

2026-09-09 사용자가 1033을 보고했습니다. 로컬 앱·Ollama는 정상 응답했지만 cloudflared 로그에 `Unauthorized: Tunnel not found`가 반복되어 기존 임시 주소로 재연결할 수 없는 상태였습니다. 기존 터널을 종료하고 주소·키를 재발급합니다.

- 등록 상실 오류를 감지하면 오래된 접속 정보 파일을 폐기하고 보호 게이트와 터널을 종료하도록 보강했습니다. 종료된 링크를 만료 시각만 보고 유효하다고 안내하지 않습니다.
- 새 주소는 연결 등록, 공개 DNS와 실제 보호 게이트 응답까지 확인한 뒤 저장합니다. 주소 발급 직후 DNS 반영 지연에는 제한된 재시도를 적용합니다.
- Mac에서는 터널이 켜진 동안만 유휴 시스템 잠자기를 방지합니다. 화면 잠금 설정은 변경하지 않습니다. 이번 오류의 원인이 잠자기였다고 확인된 것은 아닙니다.
- Quick Tunnel에는 가용성 보장이 없으므로 8시간 유효하다고 단정하지 않습니다. 이후 링크 안내 전에는 실제 외부 응답을 다시 확인합니다.

복구한 새 주소에서 2026-09-09 Chrome으로 관리 화면 로그인·프로젝트 목록과 샘플 앱의 로그인·서버 데이터 로딩·모바일 표시를 재검증했습니다. 사용자 체크리스트나 메모는 변경하지 않았습니다.
