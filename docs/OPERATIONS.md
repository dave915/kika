# 로컬 운영과 회사 환경 전환 메모

## 로컬 상태 확인

`GET /api/health`에서 local 모드, AI 공급자 `OLLAMA`, 나머지 회사 연동의 `NOT_CONFIGURED` 상태를 확인합니다. 관리 UI 오른쪽 위의 계정 메뉴에서 역할을 바꿔 볼 수 있습니다.

- 일시 중지: 프로젝트 → 설정 → 프로젝트 실행 끄기.
- AI 중지: 프로젝트 → AI → AI 기능 사용 끄기 → AI 설정 저장. 모델 연결 실패 중에도 차단할 수 있습니다.
- 데이터 쓰기 중지: 프로젝트 → 설정 → 데이터 쓰기 끄기.
- 롤백: 프로젝트 → 리비전 → 이전 버전의 롤백 검토. 데이터는 그대로 유지됩니다.
- 문서 복구: 데이터 → 해당 컬렉션 → 휴지통 → 문서 선택 → 문서 복구.
- 잘못된 공유 축소: 공유 및 권한에서 나만 보기로 변경하고 저장. 공개 확대는 게시 검토를 사용합니다.
- 소유자 이전: 최도윤 계정 → 전체 프로젝트 → 설정 → 소유자 변경.
- 오래된 승인 취소: 게시 승인에서 요청 취소 후 리비전에서 다시 요청.

## 로컬 백업

DB와 리비전 파일의 일관된 복사에는 서버를 정상 종료한 뒤 `.data/` 전체를 백업합니다. SQLite를 실행 중인 채 DB 파일 하나만 복사하지 마세요. 토큰 암호화 키를 사용했다면 승인된 별도 비밀 백업 절차로 보존해야 합니다.

복원은 서버를 중지한 상태에서 `.data/`를 교체하고 앱 파일과 활성 리비전을 점검합니다. 현재 자동 복구 검증, 정리 작업, 보존 기간 이후 물리 삭제는 구현되지 않았습니다.

## 운영 환경 구현 순서

1. Keycloak 관리·실행·MCP 클라이언트 및 사용자 토큰 교환을 구현하고 실제 환경에서 시험.
2. 확정된 회사 DB에 Repository·마이그레이션·역할별 계정·격리 정책을 구현.
3. 운영 host-only Secure 쿠키와 HTTPS 오리진 강제. local 자동 로그인·사용자 전환 제거.
4. nginx auth_request, 내부 인증 라우트, 정적 앱 라우팅, 이전 해시 자산 보존·GC 구현.
5. STaRT/Trace 프록시·예산·스트리밍·응답 제한 구현.
6. 감사 writer·스풀·외부 앵커·장애 임계치 구현.
7. 백업·복구·부하·보안 검증 후 제한된 인사팀 파일럿.

운영용 nginx/systemd 파일을 ‘바로 사용 가능’한 것처럼 넣지 않았습니다. 현재 인증·DB·감사 통제는 로컬 개발 수준이며 공개망이나 운영망에 노출할 준비가 되지 않았습니다.
