# 실제 접속 테스트용 샘플 앱

사용자 요청으로 `오늘의 작은 성공 · 샘플 앱`을 등록하고 게시했습니다.

| 항목        | 값                              |
| ----------- | ------------------------------- |
| 프로젝트 ID | `kika-first-steps`              |
| 게시 리비전 | `r1`                            |
| 상태        | ACTIVE (게시됨)                 |
| 공개 범위   | PRIVATE                         |
| 위험 등급   | R1                              |
| 실행 경로   | `/apps/kika-first-steps/`       |
| 소스        | `examples/first-steps/`         |
| 저장소      | PERSONAL 모드의 `boards` 컬렉션 |

## 직접 해볼 수 있는 것

- 체크리스트 완료 표시와 진행률 확인.
- 최대 20개의 할 일 추가·삭제.
- 최대 500자의 메모 저장.
- 새로고침 또는 새 브라우저로 같은 사용자 세션에 접속하여 저장 내용 확인.
- ‘처음부터 해보기’로 본인의 샘플 데이터를 초기화.

실제 플랫폼 SDK의 `db.get`·`db.set`을 사용합니다. 브라우저 localStorage로 저장을 흉내내지 않습니다. 서버 세션의 사용자별로 문서를 나누고 ETag 충돌을 처리합니다. 미리보기에서는 저장을 막고 게시된 앱에서 사용하도록 안내합니다.

현재 개발용 런타임은 체험 사용자 김하늘로 로그인합니다. 개인 원격 링크를 공유하면 같은 체험 사용자 데이터에 접근할 수 있으므로 본인의 테스트용으로 사용합니다.

## 검증 결과

2026-09-09 실제 Cloudflare 원격 주소와 Chrome에서 다음을 확인했습니다.

- 원격 접속 키 로그인 후 실제 앱 로딩.
- 체크·항목 추가·메모의 서버 저장.
- 새로고침 후 저장된 내용 복원.
- 별도 브라우저 컨텍스트와 390px 모바일 화면에서 내용 유지 및 가로 넘침 없음.
- 초기화 후 기본 4개 항목·빈 메모로 복원.
- 브라우저 JavaScript 오류 없음.

실제 배포 검증 중 `.data/` 아래에 저장된 앱을 Express가 숨김 파일로 오인해 404로 처리하는 문제를 발견했습니다. 승인된 dist 디렉토리를 `sendFile`의 root로 지정하도록 수정했으며, 요청된 숨김 파일은 계속 거절합니다. 전용 회귀 테스트를 추가했고 전체 서버 테스트 55개가 통과했습니다.

관리 화면에서 이 프로젝트의 **개요 → 앱 열기**로 접속할 수 있습니다. 원격 접속 키는 문서에 기록하지 않으며, 현재 접속 정보는 `.data/remote-preview.json`에서 관리합니다.
